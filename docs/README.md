# Партнерські звіти на Bolt Food UA — методичні матеріали для команди

Цей розділ — **внутрішня база знань** для команди Stores Ukraine. Тут зібрано все, що треба, аби самостійно створити автоматичний звіт для будь-якого бренда-партнера, дані для якого підтягуються напряму з Databricks та публікуються через GitHub Pages як живе посилання для партнера.

> **Що означає «автоматичний звіт»**
>
> 1. Дані тягнуться з Databricks SQL Warehouse напряму, без проміжних експортів у Excel.
> 2. HTML-звіт перегенеровується щотижня (понеділок 08:00 за Києвом) через GitHub Actions.
> 3. Партнер отримує одне постійне посилання — **GitHub Pages URL**, який завжди показує найсвіжіші дані.
> 4. Будь-яку правку (нова метрика, новий розділ, фікс чисел) робиш через агента в Cursor — він сам генерує звіт і пушить його на Pages.

## Вибір шаблону звіту

Є два рівні звітів. Обирай за потребою партнера:

| Шаблон | Вкладки | Коли використовувати | Приклад |
|--------|---------|----------------------|---------|
| **Простий (Hop Hey-like)** | Monthly + Weekly | Партнер хоче бачити фінансові і операційні KPI у динаміці | [Hop Hey](https://github.com/mykhailobrynchak-dev/hophey-qbr-reports) |
| **Повний (LOKO MBR-like)** | Monthly + Weekly + Stores + Failed orders + Customer feedback | Велика мережа (10+ магазинів), партнер хоче drill-down по точках і коментарі клієнтів | [LOKO MBR](https://mykhailobrynchak-dev.github.io/loko-mbr-report/) |

Шаблони і промт у цьому репо — на базі **Hop Hey** (простий). Якщо потрібен повний — кажи агенту: «Зроби як LOKO MBR» і дай йому посилання на той репо як зразок.

       ┌──────────────────────────────────┐
       │  Публічний репо <partner>-report │

Паралельно — **GitHub Actions** у тому самому публічному репо щопонеділка о 05:00 UTC автономно перегенерує звіт зі свіжими даними (без участі людини).

## Кому надавати посилання

- **Колегам** (команда Stores) — на цей репо: `https://github.com/mykhailobrynchak-dev/Stores-internal-weekly-report/tree/main/docs`
- **Партнерам** — лише на готовий публічний репо звіту (`https://mykhailobrynchak-dev.github.io/<partner>-report/`)

## Правила безпеки

- **Ніколи** не комітити `.env` з реальним Databricks PAT (у `.gitignore` він уже є).
- Код генерації (`generate_report.py`, SQL-запити) тримати **локально** в `Reports/<PARTNER>/` — у публічний репо йде **лише** `index.html`.
- Коментарі клієнтів і номери замовлень — це чутливі дані; перед тим як відкрити Pages партнеру, переконайся, що все що там є — він має право бачити.

## FAQ

**Q: Скільки часу займає створити новий звіт?**
A: З готовим промтом — 15–20 хвилин (більшість часу — Databricks-запити). З нуля без агента — ~півдня.

**Q: Чи можна оновлювати звіт частіше, ніж раз на тиждень?**
A: Так. У GitHub Actions workflow міняй `cron` (або запускай вручну Actions → Run workflow). Денне оновлення не рекомендуємо — Databricks квоти.

**Q: Хто платить за Databricks-запити?**
A: SQL Warehouse `b39957853740b21d` — це shared warehouse команди. Один звіт виконується ~1–2 хв, навантаження мінімальне.

**Q: Що робити, якщо партнер просить нову метрику?**
A: Скажи агенту в Cursor: «Додай метрику X у звіт партнера Y» — він знайде правильну колонку в Databricks, додасть SQL-запит і оновить шаблон.
